# DocuQuery evaluation harness

Reproducible measurement of retrieval quality and pipeline performance.

Nothing here is used by the running application. Every script writes its raw
output to `results/` as JSON so a number in a report can be traced back to the
run that produced it.

## Prerequisites

    docker compose up -d db          # from backend/
    alembic upgrade head

Set `EVAL_DATABASE_URL` if the evaluation database is not the one in `.env`.

## Scripts

| Script | What it does |
|---|---|
| `ingest_corpus.py` | Ingests a folder of documents through the real ingestion pipeline under a synthetic eval user, recording per-stage timings. |
| `build_eval_set.py` | Builds a ground-truth query set from indexed pages. Queries are generated by the configured LLM from page passages; ground truth is the source `(document, page, passage)`. |
| `run_retrieval_eval.py` | Runs the query set through the real retrieval pipeline and computes Recall@k, Precision@k, MRR, Hit Rate, NDCG@k at document / page / passage level. |
| `run_config_sweep.py` | Re-ingests the corpus under different chunking and retrieval configurations and compares them on the same fixed query set. |
| `run_perf_bench.py` | Per-stage ingestion timings, retrieval latency percentiles, LLM TTFT and generation latency, throughput, memory. |

## Methodology notes

- The eval set is **synthetic**: queries are LLM-generated from passages in the
  corpus, not written by humans. Ground truth is the passage the query was
  generated from. This is a standard way to build a retrieval test set when no
  labelled data exists, and it is stated wherever the numbers are reported.
- A generated query may legitimately be answerable from more than one passage.
  Passage-level recall is therefore a **lower bound**; document-level recall is
  the looser, more forgiving figure. Both are reported.
- Ground truth is anchored to `(document_id, page_number)`, which is independent
  of chunk size. This is what makes the chunking sweep a fair comparison.
- Query generation happens once, before any retrieval run, and the generator
  never sees retrieval output. No query is added, removed, or edited after
  seeing a score.
